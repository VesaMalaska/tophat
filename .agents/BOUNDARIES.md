The work hierarchy is **Development Phase → Sprint Chunk → Task**. A **Workflow Stage** identifies operational progress, such as session start, implementation, review, or QA. The Architect's Proposal Stage and Issue Creation Stage are operational stages, not roadmap segments.

## Slice 9 acceptance evidence

The invoked read-only acceptance verifier checks a closed criterion index, candidate identities, supplied artifact hashes/classifications, latest supplied attempt, and existing host project lifecycle evidence. `EVIDENCE_COMPLETE` means supplied records are consistent; it is not release authorization, cryptographic human identity, proof of actual execution, or proof of complete history. Recorded provenance cannot authenticate itself. Fixture/config tests do not certify real applications, browser journeys or native operating systems. A synthetic positive dossier in tests is parser/mechanism evidence only.

Artifact custody, secret redaction, honest observed execution, independent semantic review and explicit scope/release decisions are orchestrator/human obligations. Streaming size checks and path validation bound invoked inspection; they do not create an OS sandbox, universal interception, transaction lock or race immunity. No host project live acceptance or release is claimed while required host inputs/completion remain pending.

## Command packaging boundaries

The invoked read-only closed catalog validator checks metadata, paths, installed dependencies and model mappings. It is not a dispatcher, permissions runtime or proof of agent obedience. Roles load explicitly; external checks/custody/application stay separate from PM/review/audit. Catalog resource closure and ownership inventories support inspected installs/upgrades, without atomicity or automatic recovery.

The Context guard recognizes the canonical `### 🎯 Active Sprint Chunk:` marker (including CRLF/trailing whitespace and existing inline titles), rejects missing/duplicate full-write markers and asks on removal/insertion or absent original replacement context. Marker presence does not prove protected content is unchanged or approved. Swarm coordination uses Git common metadata across linked worktrees, exclusive create and exact owner release; failed/aborted owners require human inspection. Neither claims universal interception or race immunity.

## Terminal extension boundaries

The human-approved terminal amendment adds deterministic profile/capability, highest-tier routing, topic/method and closed QA metadata checks. Sizes have one typed source; nonterminal reports reject terminal metadata, and actual config owns kind/framework/mode. Identity bounds reject placeholders but cannot prove the declared emulator/harness was observed. Passed terminal methods require artifacts; digests cannot certify visual correctness.

Generic native Linux fixtures observe Node input/resize, normal/error/SIGINT exits and PTY termios restoration using util-linux script and GNU stty. Renderer/glyph/font behavior, real product integration, other OS execution and IDE interception remain unverified. No new command, universal OS sandbox, renderer engine, automatic dependency installation or receipt migration is supplied. See `.agents/docs/terminal-host-support.md`.

## Hook transport candidate

The direct Node adapter derives the selected host from its own module and preserves unchanged lock/policy contracts. Its pre-write handler checks protected-write/framework decisions before locking; post output is event-specific. Closed exploration and known read-only validator calls do not require Git. Positive macro identity is still unverified, so other command calls visibly block with MACRO_APPLICABILITY_UNVERIFIED; there is no automatic macro reservation or all-command exemption. A physical synthetic probe on Antigravity 2.19.1 observed deny enforcement, relative Node/CJS launch and force_ask rejection/approval. Approval did not rerun the pre handler; the production ask path and required reservation after approval remain blockers. Production adapter integration, multi-root, cached-grant and error/interruption handling also need observation before merge or cutover. See `.agents/docs/antigravity-hook-support.md`. Concurrency redesign and recovery remain separate proposals.
