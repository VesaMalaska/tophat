# TopHat boundary registry — through Slice 8

This registry distinguishes current mechanisms from instructions and planned work. A registered hook is not automatically a reliable fail-closed control.

| Boundary | Current classification | Evidence and limit |
|---|---|---|
| Workspace contract parsing and capability derivation | Deterministic when `loadTophatConfig` is called | The loader denies malformed or unsupported declarations and returns frozen data. The vault template is intentionally unconfigured. Other scripts are not wired to this loader until their owning slices. |
| IDE hook decisions and context locks | Deterministic when called; host interception unverified | Registered scripts deny malformed payloads, unknown lock owners, and filesystem failures. A live `PreToolUse` probe in standalone Antigravity IDE v2.5.5 did not fire; no physical IDE write or command interception is claimed. `context-lock.ts` was unregistered and has been removed. Stale locks require owner inspection rather than PID-only deletion. |
| Svelte syntax guard | Deterministic when called; host interception unverified | The script loads validated host config; Svelte profiles enforce, valid non-Svelte profiles explicitly skip, and invalid input/config denies. IDE registration is not proof that a write is intercepted. |
| Framework skill compatibility | Deterministic when the guidance command is invoked; task handoff is instructed | `select-task-guidance.ts` checks proposed skill labels and framework instructions against derived capabilities and task topics. Architect/task-generation instructions require it before proposal and issue creation. The host does not physically prevent an agent from ignoring those instructions or writing contradictory free-form prose. |
| Smoke profile | Deterministic profile output, instructed task content | Selection reports web/backend/desktop from validated config. The smoke workflow describes compatible checks; execution and full QA classification remain later work. |
| Host-declared validation execution | Deterministic when invoked | `run-validation.ts` preflights every selected host script and executes `pnpm run` in order. Selected missing or failing scripts deny; an empty optional gate reports `SKIPPED_NOT_APPLICABLE`. The project owns coverage thresholds. Git state changes during checks deny a passing report. |
| Commit validation boundary | Native Git hook after explicit installation | `install-git-hook.ts` refuses existing hooks and redirected `core.hooksPath`; the installed `pre-commit` script runs the shared executor. A real fixture commit failed with unchanged `HEAD`, then passed after the script passed. Installation is per clone, and `--no-verify` or another Git hook configuration can bypass it. The tested standalone IDE hook did not intercept the command. |
| Documentation package structure/integrity | Deterministic when the read-only validator runs | Closed v1 schema, safe files, exact-byte hashes, metadata fingerprint, dependency/ownership/trace checks. All named planning/task workflows require invocation; instructions do not physically intercept planning. |
| Task authority/source extracts | Deterministic when the task checker runs | Fresh approved authority and private chunk provenance; typed active references and exact source-block equality. Semantic relevance and exact issue handoff remain instructed; no physical prevention of agent bypass. |
| Definition approval/finalization | Manifest publication gate when finalizer is invoked | Matching review/approval receipts, candidate fingerprint, review digest, explicit signal and ordered timestamps are required before manifest-only publication. Receipts prove recorded consistency, not human/reviewer authentication or that the event genuinely occurred. Semantic completeness/consent are human-supervised. |
| HUD documentation state | Read-only current-state detection | Revalidates on render with polling fallback; stale approved prose cannot override checks. Temporary inaccessible files deny readiness. It does not enforce workflow execution. |
| Attachment discovery/readiness | Read-only deterministic checks when invoked | Candidate config is inspected in memory; proposal/script/snapshot/package/approval consistency and exact application postconditions are checked. No helper writes host files; agent application is instructed and postchecked. Receipts do not authenticate consent. |
| Attachment baseline | Authorized host execution and postcondition detection | Runs selected project pnpm scripts with timeout/output bounds and no automatic pnpm setup. Checks all exits for tracked/index/history/artifact changes. Scripts/descendants are not an OS sandbox or memory-isolated. |
| Manual detachment | Read-only inventory plus instructed human removal | Exact current ownership/removal and preservation checks; helper never deletes. Mixed paths/hooks/exclusions require a new human decision. |
| Task route and QA methods | Deterministic when classifier is invoked | Closed declaration, current authority/guidance and fixed tier/method rules; contradicting metadata denies. Trait completeness and exact issue transport remain semantic/instructed. |
| QA evidence and publication readiness | Deterministic consistency check when invoked | Exact candidate, latest supplied attempts/stages, criterion/method coverage and artifact/runner-log integrity. Every later commit invalidates QA, including private-state commits. Receipts do not authenticate identity, actual execution, complete history, or consent; arbitrary publication can bypass invocation. |
| QA product-code read-only boundary | Instructed plus postcondition detection | Explicit artifact outputs, bounded pre/post snapshots and reported operation checks; surviving writes or observed forbidden operations reject the result. No OS sandbox, invisible-command proof or physical IDE prevention. Separate developer remediation and independent re-QA are required. |
| PM/Sprint Briefing | Instructed plus externally supervised detection | No command/file/Git/HUD/Linear mutation exception. Orchestrator captures/verifies outside PM session. Failed/unavailable inspection is visibly unverified. Tested host interception/workflow identity remains unproven, so no role hook is registered. |
| Derived documentation lifecycle | Deterministic consistency/readiness checks when invoked | Phase/completion reports require integrated task evidence, unchanged authority/config, exact safe plan, independent document review/checks/claim verification and current candidate. No-change is explicit; immediate mode cannot accept a phase. Receipts do not authenticate consent, identity, execution or complete membership/history. |
| Technical writer | Instructed plus externally supervised detection | No command/Git/Linear/product/authority/private-state mutation. Git/filesystem comparison rejects surviving or reported forbidden actions, but no physical IDE interception/read sandbox/invisible-action proof or automatic rollback exists. SVG active content remains independent semantic review. |
| Document publication | Explicit invoked workflow gate | Documentation-only candidates start from accepted integrated tasks and contain only authorized derived diffs; combined candidates retain fresh Slice 6 task evidence. Later commits invalidate readiness; historical approval is not refreshed QA. No server-enforced GitHub publication policy. |
| Agent context restrictions | Instructed | No physical read sandbox is claimed. |
| Git mutation safety | Deterministic read-only preflight when invoked; mutation execution is instructed | Closed operation profiles inspect exact branch/HEAD/index/intended bytes, conflicts, remotes and metadata. Workflows require sequential checked actions and postconditions. No universal interception, atomic transaction, consent authentication or autonomous recovery; another process can race. |
| Hook installer Git safety | Invoked precondition at the existing write boundary | Installer requires explicit metadata request and calls shared preflight immediately before write/chmod; it retains existing hook/hooksPath refusals. It does not intercept other Git mutations. |
| Workflow postcondition checks | Detection where actually performed | A diff or state audit can reject a result after a mutation; it does not prevent that mutation. Later slices must record both separately. |

The work hierarchy is **Development Phase → Sprint Chunk → Task**. A **Workflow Stage** identifies operational progress, such as session start, implementation, review, or QA. The Architect's Proposal Stage and Issue Creation Stage are operational stages, not roadmap segments.

## Slice 9 acceptance evidence

The invoked read-only acceptance verifier checks a closed criterion index, candidate identities, supplied artifact hashes/classifications, latest supplied attempt, and existing host project lifecycle evidence. `EVIDENCE_COMPLETE` means supplied records are consistent; it is not release authorization, cryptographic human identity, proof of actual execution, or proof of complete history. Recorded provenance cannot authenticate itself. Fixture/config tests do not certify real applications, browser journeys or native operating systems. A synthetic positive dossier in tests is parser/mechanism evidence only.

Artifact custody, secret redaction, honest observed execution, independent semantic review and explicit scope/release decisions are orchestrator/human obligations. Streaming size checks and path validation bound invoked inspection; they do not create an OS sandbox, universal interception, transaction lock or race immunity. No host project live acceptance or release is claimed while required host inputs/completion remain pending.
