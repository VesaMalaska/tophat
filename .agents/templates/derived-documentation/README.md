# Derived document receipt examples

Exact v1 types are exported in `validate-derived-docs.ts` and `inspect-derived-doc-session.ts`. `tests/fixtures/derived-docs.ts` constructs complete runnable synthetic phase, immediate and completion records. Replace every synthetic identity/observation with actual evidence; copying an example does not authorize work or prove execution.

## Phase with changes

Accepted integrated task provenance and baseline phase check → explicit target plan and human approval → external writer capture/postcondition → orchestrator's documentation-only candidate → current checks/claims → independent sealed document review → readiness → exact human acceptance. Output is DOCUMENTATION_ACCEPTED only after validation.

## Phase with no change

Assessment outcome NO_DOCUMENTATION_CHANGE_REQUIRED includes complete source/task coverage and rationale. Plan is empty and writer null. Independent review, claim assessment and applicable checks remain mandatory. Output is never an implicit skip or automatic phase acceptance.

## Immediate and final

Immediate necessity is fingerprinted in one task, with one of the five bounded reasons and rationale. Output is IMMEDIATE_DOCUMENTATION_ACCEPTED, never phase acceptance. Final mode requires accepted phase receipts, exact combined task membership, current completion checks and each handoff coverage dimension. It returns PROJECT_DOCUMENTATION_ACCEPTED only after separate human acceptance.

Evidence examples are contract fixtures, not live browser, SVG safety or authenticated human approval proof.
